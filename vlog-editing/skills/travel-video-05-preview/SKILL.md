# Stage 5 · 可播放预览与下载交付

将实际渲染的视频交付为可播放、可下载的预览，并将反馈精确带回剪辑阶段。读取本地版本、FCP 验证和当前发布状态；本地最新版与线上版本分别记录。

## 渲染与质量
- 已完成导出的 SDR 媒体可用总 Skill 的 `scripts/make_preview.py` 生成轻量预览与解码/hash 记录，见 [工具约定](../../references/python-tools.md)。它不渲染 FCPXML，也不代替实际播放、听感或线上下载验证。
- 从同一版本的时间线生成适合设备的预览。手机常用 H.264 + AAC、兼容像素格式、faststart；分辨率/码率依据实际上传和播放限制选择，不用固定“47 MB”作标准。
- 单独保存高清导出与轻量预览。FCP 与外部渲染效果不一致时明确差异；外部近似预览不等于 FCP 已成功导出。
- 检查完整解码、时长、首尾、音画同步、峰值/响度、HDR→SDR 显示、方向。响度检测不能代替听感；实听不能完成时保留未确认项。
- 按反馈逐段回放改动及两侧接点，尤其音乐断点、完整对白、地图路线、标题基线、过曝、指定露脸删除和 room tour。变更时间后需映射旧版时间码，不能拿旧 6:41 直接删新版 6:41。

## 预览链接
- 本地可播放文件是默认交付。用户请求链接、上传或外出查看时，再在授权的服务和受众内发布；历史某次上传不授权以后持续同步。制作这套 Skill 不等于授权上传未来旅行视频。
- 使用 Sites 时读取当时可用的 sites-building/sites-hosting，复用已登记项目，保留现有隐私受众；不要把私人预览改成公开链接解决访问问题。其他指定服务按其工具工作流操作。
- 大视频超过单资产限制时可用兼容 HLS 分段播放，但仍提供完整 MP4 下载。优先稳定普通链接和附件下载响应；不要把 playlist 当 MP4。
- 私密站点的服务器自请求可能被登录门禁拦截。根据宿主实际支持的内部静态资产/存储读取接口实现流式下载，避免整片缓冲、硬编码临时凭证或擅自扩大访问。`env.ASSETS` 只是在确认支持的 Cloudflare 部署中的实现选项，不能凭本地成功认定线上可用。

## 必须区分的验证
1. **本地文件**：实际存在、正确时长、完整解码、版本与 hash。
2. **发布状态**：部署终态成功及准确 URL，不以保存版本/上传完成代替上线。
3. **播放**：在目标页面触发播放并检查视频数据实际加载、进度推进；不是仅有封面或 HTTP 200。
4. **下载**：从页面入口点击到实际保存；核对返回是 MP4、完整大小/hash，而非登录 HTML、JSON 或过期 blob。记录浏览器下载与后端字节校验分别完成与否。

沿用一个用户可见的站点标签页。线上失败时不反复重新上传整批媒体；定位失败层级，有限重试（同一发布服务故障通常最多三次），必要时恢复已知可用版本，明确本地修复与线上未完成的区别。

## 交付与反馈闭环
输出 `05_preview/preview.mp4`、`delivery.json`、验证记录，以及在当前请求范围内制作的 MP4/FCPXML/资产包。交付记录含本地/线上版本、时长、文件大小、SHA256、页面 URL、下载页 URL、受众、部署 ID 与各项检查状态。

最终给一个明确可点击的预览或下载入口和短说明。不要写“全部完成”来掩盖未导入、未听审或未上线。

新反馈保存为 `旧版本 + 时间/截图 -> 指定修改 -> 匹配的 clip_id/source range -> 新版复查结果`，按范围返回 Stage 1/2/3/4。没要求全片重剪就只改指定内容；无须重新做已验证且未变化的步骤。
