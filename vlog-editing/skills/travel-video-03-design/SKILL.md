# Stage 3 · 转场与真实包装资产

制作能放进时间线的实际素材，而不是只写 marker。读取项目记录、所选方案、资产任务与人物身份映射；可先完成一个风格样段，再按已有反馈扩展。

已有标题与地图底图/角色素材时，使用总 Skill 的 `scripts/render_title.py` 和 `scripts/render_route.py` 生成实际透明 ProRes；配置与限制见 [工具文档](../../references/python-tools.md)。这两个工具负责稳定渲染，不能代替风格设计、角色生成或地理核对。

## 角色与风格
- 先看参考图，并确认哪一位对应哪个角色；多张照片不等于多个不同人物。缺参考或映射无法确定时询问，通用角色必须明确标为占位。
- 保留已确认的角色脸型、发型、服装与耳饰侧别；圆润 Q 版、半身贴纸、不同表情只在用户选择时采用。不要每次生成换风格，也不要把头像持续盖在风景上。
- 需要栅格生成/编辑时使用当前可用的图像工具及适用技能；视频生成仅在确有需要且工具可用时采用。调用有费用或外部上传的服务应遵守当前用户授权与工具规则；不可假定某个供应商一直可用。

## 地图
- 以可核查地点坐标、真实道路/线路和实际行程证据建立底图，再制作卡通覆盖层。生成模型不负责猜地理。记录地理来源与资产许可；不需要显示精确住宅地址。
- North-up 或明确方向标记；出发点、目的地、行驶方向正确。路线简化须注明概览示意，不将直线装作实际公路。
- 根据当前项目确定车辆与乘员角色，不默认沿用旧旅行车辆。沿真实路径按弧长匀速推进并缓入缓出，方向角连续、相机平稳，不做逐帧位置抖动或瞬移。
- 开场概览与区域切换局部图有明确目的；目的地元素匹配到实拍。输出真实动画文件及可编辑工程/生成脚本。

## 标题、微动画、声音
- 建立同一套字体、字重、色彩、安全区和运动规则；检查汉字与拉丁字母基线，尤其单字逐个排版时的“一”，不按每个字墨迹顶部对齐。
- 标题根据树干、车窗、人物与留白设计，避免重复黑底模板。Day 1–4 与日期分开设置，不擅加日期。
- 趣味动画对应素材中确有的动作。可爱音效少而准，与笑点/落点同步，不编造摔倒、湿鞋或对白。
- 为对白、音乐、自然声、音效分角色安排，保留可调节文件与 cue sheet。音乐/字体/音效记录许可、来源、署名位置；移除片尾署名时确认是否可迁移到发布说明，否则换素材。

## 产出和检查
写入 `03_design/assets/`（characters、maps、titles、transitions、audio）。`asset_manifest.json` 列实际文件、生成来源/参数、尺寸、fps、时长、alpha、色彩、许可、审批状态及引用的任务 ID。
- PNG/带 alpha 视频用于覆盖；地图完整场景可用普通视频。选择 FCP 可解码的格式，实际检查透明边缘、帧率、字距、路径运动和手机尺寸可读性。
- 交付包含开场高光 → 地图出发 → 第一个体验章节的真实预览样段（或用户当前要求的样段）。标清哪些只是静态设计、哪些已动画化。
- 缺项在 manifest 标为 pending/placeholder；不可用 marker 冒充已完成的动画。样段未获反馈不标 approved，但已有授权的工作可继续。
- 更新项目记录并交接 `$travel-video-04-fcpxml`。
